📥 1. 系统的输入是什么？(3 类输入)

① 发起委托输入（飞书 `@机器人` / 网页 / CLI）：
• 一句自然语言需求：[modular-rag] 修一下 sparse_encoder 连字符分词报错
• 或直接粘贴报错日志堆栈 / 失败单测名
② 5 秒微确认输入（仅当遇到实质业务歧义时）：
• 在飞书卡片点选项按钮，或直接回一句 默认 / 1 / 2
③ 下半场追改输入（PR 打开后）：
• 直接在 GitHub PR 代码行下留评论（后台 30 秒自动感应）
• 或在飞书发 #t-20261116-xxxx 再补个空值判断

⚙️ 2. 系统在黑盒外透明做了什么？

1. 读取目标仓代码与 .ai/DECISIONS.yaml，自动切分出原子级 TaskContract；
2. 拉起隔离 git worktree（ai-agent/{task_id}），剥离敏感密钥；
3. 先在基线 Commit 跑回归单测确认 FAIL，修复后确认 PASS（防幻觉自嗨）；
4. 反作弊扫描 Diff（严禁删 assert 或加 @skip）；
5. 单审查器核对验收标准并提取沙箱未覆盖的真实风险。

📤 3. 输出给到用户是什么？(3 件交付物)

① 线上 GitHub Draft PR（绝不擅自合入主干）：
• 干净的最小化代码补丁 + 线上真实 GitHub Actions CI 绿灯
② 飞书结构化证据卡片（分阶段主动推送）：
• 蓝色《已受理回执卡》 / 橙色《5 秒拍板卡》
• 绿色《证据门禁报告卡》（含 Fail-to-Pass 结果、费用、⚠️ 未验证盲区披露 与一键跳 GitHub 审阅按钮）
③ 兜底结构化交接包 (Handoff)：
• 若超步数或缺系统库无法独立完成，输出已排查根因与保留分支现场，零白费功夫。
